# Android CLI and repository skills

## Android CLI installation (local user only)

The official Google Android CLI is installed for this macOS ARM64 user at `~/.local/bin/android`, currently version `1.0.16500706`. Its executable was fetched from the official direct binary URL `https://dl.google.com/android/cli/latest/darwin_arm64/android` (SHA-256 observed at install: `52618946fb521fa08de5729181d12cb9190a5d6a2e8e869f71799808bc82792e`). The official installer was inspected but not run: it edits shell startup files and invokes the new CLI without `--no-metrics`. The direct official binary was installed without `sudo` and without changing shell profiles.

Google's Android CLI documentation says `.androidrc` applies flags to each invocation, one per line. Since no `.androidrc` existed, `~/.androidrc` now contains only `--no-metrics`; existing files should be preserved if configuring another workstation. Explicitly use the flag too:

```sh
~/.local/bin/android --no-metrics --version
~/.local/bin/android --no-metrics --help
~/.local/bin/android --no-metrics info
~/.local/bin/android --no-metrics skills list
```

The first version invocation downloaded/unpacked the CLI's embedded installation. Android SDK Platform 36 was installed into the existing SDK at `/Users/srinath/Library/Android/sdk` using the official CLI and licenses already accepted during Android Studio setup; Build-Tools 36.0.0, Build-Tools 35.0.0, and platform-tools are present. No new license prompt appeared, no license was auto-accepted, and no emulator/system image was installed. No auth/login was performed, and no Google Cloud project was linked. Android Device Streaming can involve authenticated, billed device reservations; it remains disabled and must not be enabled as part of these local tests.

Official references:

Source is the official `android/skills` repository at commit `42dc2270e96032bd860bb94511e440aa00a43125` (main, fetched during setup). Each skill includes its full source references and an Apache 2.0 `LICENSE.txt`. No bundled executable scripts were present in these selected skills. Skill Markdown, references, and the upstream license were read before copying. Android CLI project-scoped `--agent=pi` placement used `.pi/skills`; the temporary test of that path was removed after confirming the repository's Pi integration uses `.agents/skills`, and the exact official skill subtrees were copied to that supported project path instead.

Skills are reference material, not permission to widen SnapBudget scope. Existing repository policies take precedence: offline/local-only data, fixture-based tests, no production/UI feature changes from this tool setup, no CI/device-streaming cloud runs, and no acceptance of SDK licenses without the user's explicit setup step. The testing skill's generic suggestions (for example Hilt, Robolectric, screenshots, or CI) were not applied automatically.
